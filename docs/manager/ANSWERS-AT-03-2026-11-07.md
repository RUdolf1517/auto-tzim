# Answers for the coder — AT-03, 2026-11-07

Copy-paste source for the message sent in chat, and the same text is posted as a comment on PR #46. Eight questions, five

## 0. Two sentences first

The questions were the right ones to ask and none of them was pedantic: each one sat on a place where two documents disagreed or
where a document was silent. All of them now have an answer, so **a valid `scan` must exit `0` and print a plan at the final
head** — "exits `7` rather than guess" was honest while the contract was open and is a blocker now that it is not.

## 1. `argv` — what a plan records (D-59)

**Neither `--json` nor an absolute path.**

| Element | AT-03 writes | Why |
| --- | --- | --- |
| profile flags, fixed order, values byte-sorted | `--formats png,gzip` only when `formats` is non-empty | the part the user chose; the part D-11 says is ours to pass |
| `--` | **always**, before the path | a name may start with `-` (`N-09`); the separator is not optional |
| the file argument | the **relative POSIX path** | an absolute path would make the plan hash depend on where the tree lives, and D-52 exists so two machines agree on an unchanged tree |
| `--json`, `--jobs`, `--strip-metadata`, the staged path | nothing | adapter territory (AT-04). Do not invent it |

AT-04 will prepend its flags and replace the last element with the staged copy's path. That is a **different** argv, the hash
changes, and an old plan is refused with exit `6` — which is exactly what should happen, so this is not a seam you have to
protect.

## 2. Byte-identical, with different ids (D-59)

You read it correctly: **the rows**, not the file. `plan_id`, `created` and any mode/timestamp *must* differ; the `rows` array
and therefore `plan_hash` must be identical. `GATES.md` AC-1 says "the two plan **bodies**" and means the same. Assert both
halves in one test: rows equal, hash equal, ids different.

## 3. A non-UTF-8 name in `argv` (D-59)

`argv` in the canonical row is an array whose elements are JSON strings when the bytes are valid UTF-8, and
`{"b64":"<base64>"}` when they are not. Only the path element can be non-UTF-8 in practice, but the encoding should not depend
on that. Human rendering stays lossy and never feeds the hash.

Same rule for a **root** that is itself non-UTF-8: record `root` (lossy, display) **and** `root_raw_b64` (exact). Do not reject
such a root — `N-17` exists because names are bytes.

## 4. Publishing a plan without ever overwriting one (D-60)

Your proposal is accepted, and it is better than what `state.md` §2 assumed:

```text
write plans/<id>.json.tmp   (0600, fsync the file)
fs::hard_link(tmp, plans/<id>.json)   → EEXIST means the id is taken
unlink(tmp)
fsync the directory
```

`hard_link` is `std`, creates the destination only if it is free, and fails with `EEXIST` otherwise — the create-if-absent
semantics `rename` does not have. Collision ⇒ `plan_id_collision`, **exit `7`**, the existing plan untouched, the temp removed.
No fallback that can overwrite: on a filesystem without hard links the publication fails loudly with the OS error. With a
128-bit random id a collision is a broken-randomness event, so the reaction is an internal error, not a retry — a retry loop
would hide the only symptom.

## 5. The traversal race (D-64)

Best-effort is accepted, and the claim has to be the narrow one:

| Guaranteed | How |
| --- | --- |
| no published plan contains a row outside the canonical root | the per-candidate canonical check aborts the scan (`tree_changed`, exit `6`), never a skip |
| a swap is detected | `(dev, ino)` of each directory captured before enumeration and compared after |
| nothing in the folder is written | there is no write path in this stage at all |

**Not guaranteed**, and now written in `limitations.md` §3a: that we never `lstat` a name outside the root during a swap, or that
a message never mentions one. Closing the window needs `openat`/`fstatat` with `O_NOFOLLOW` — `libc` and `unsafe`, refused by
D-35/D-38 — or a crate wrapping them, refused for the same reason.

**The re-check must be reachable through an injected seam** (a hook called after enumeration, before the comparison), so the
test performs the swap deterministically instead of racing. Same discipline as the injected clock (D-14): a test that sleeps and
hopes is a flaky test with a slow half-life.

## 6. Format policy — and a contradiction that was mine (D-62)

Your reading is right and the contradiction was real. Two different things had been written with the same words:

- **our policy** — which files we offer. `formats = ["png"]` filters, and a `.gz` is `skipped_policy` (`P-02`).
- **`tzim`'s capability** — what it can do. That is `--capabilities`, never inferred, never guessed (invariant 18).

`D-26` item 3 said "`--formats` is still never passed", which conflated them. **Corrected:** the flag is passed exactly when the
profile sets `formats`; what is never derived from the capability document is the list itself.

The table, fixed so two implementations cannot differ (D-62): `png`→`.png`, `gzip`→`.gz`, `zip`→`.zip`, `ico`→`.ico`,
`jpeg`→`.jpg`/`.jpeg`, `tiff`→`.tif`/`.tiff`, `zlib`→`.zlib`. Match the **last** suffix, ASCII case-insensitively, no suffix
never matches. **No file is opened, no signature is read** — and a file whose contents disagree with its name is still selected,
because the plan is not a promise (D-23) and `tzim` will say `unsupported` if it disagrees.

## 7. Globs (D-63)

Exactly three wildcards: `*` = any bytes except `/`, `**` = any bytes including `/`, `?` = one byte except `/`. **Everything else
is literal** — `[`, `]`, `\`, `{`, `}`, `!` included. No classes, no escapes, no braces, no negation in v0.1: they turn into a
specification of their own (ranges, collation, escaping a metacharacter) and then into a compatibility promise.

So there is no such thing as a "malformed pattern" at match time. The one refusal is an **empty** pattern (`exclude_globs =
[""]`): a configuration error at load, `exclude_globs: empty pattern`, because it matches nothing while looking like it excludes
something. Matching is over the relative POSIX path as bytes.

## 8. Gate order, and the hard-linked orphan temp (D-61)

Gate 1 wins: **no row at all**, one `orphan_temp` diagnostic. `hardlink_skip` would produce a row about a file that is not ours
to touch, which contradicts "never planned, diagnostic emitted" (`K-12`).

The whole order, now contract:

```text
excluded name → scope (depth, mount, recursive) → type → hard link → age → format → planned
```

Hard link before age and format is deliberate: two links to one inode are one file's bytes under two names, and a plan whose
rows disagree about the same bytes is worse than a smaller plan.

## 9. The no-follow negative control (no decision needed)

Accepted as you ran it. The control's job is to show that `lstat` is load-bearing, and it does: with `stat` the no-follow test
goes red. That the containment guard catches the escape *first* is defence in depth, not a failure of the control — and
requiring an actual outside row would mean disabling two guards at once, which proves less, not more. Say in the handoff that
the guard aborts before the row is produced; that is the accurate sentence.

## 10. The 10 000-entry budget (D-65)

There was no number anywhere — a requirement that cannot fail is not a check. Now there is one: one directory, 10 000 regular
files, **debug** build (that is what CI runs), `ubuntu-24.04`, walk + policy + plan rows under **15 s**, fixture creation
excluded, and the test prints the observed number so the PR can quote it. A smoke bound, not a benchmark: it exists to catch an
accidental quadratic (a canonicalise of the whole root per row), not to police CI load.
